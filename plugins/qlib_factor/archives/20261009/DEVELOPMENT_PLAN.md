# Alpha158 横截面环境增强版开发计划

## 目标与边界

复制 `plugins/qlib_a158` 为独立插件 `plugins/a158_factor`，保留原始158个特征、标签、样本过滤、LightGBM参数和回测成交假设。增加成交金额活跃度、市场环境、个股相对表现和少量交互，寻找样本外 RankIC 与扣费后 TopN 的稳定增量。不下载 daily_basic，不将成交金额分组称为大小市值分组，不预先保证提升。

执行遵循 `../../docs/zh/dev_guide.md`。独立发行包 `axonx-alpha158-enhanced`、Python 包 `axonx_alpha158_enhanced`、插件入口 `alpha158_enhanced`、Task 注册名前缀 `a158e_`。保留原插件和已有任务。所有研究任务提交到 用户指定的远程 AxonX 服务（地址仅保存在本地配置），凭据由现有环境配置加载，不写入文档或产物。

## 数据与时点

- 使用远程已有 Tushare daily、adj_factor、交易日历、历史名称与涨跌停数据。当前已有基线 ETL 覆盖2015-01-05至2026-09-30，共11,441,741行。
- 信号为 T 日收盘后，输入最多使用 T 日行情。收益使用复权价格；成交金额使用原始 `amount`。
- 市场统计池为沪深当日有效交易股票，排除缺失或零成交行，保留涨跌停股票。不使用未来标签、退出日期或未来可卖性筛选统计池。
- 成交金额组使用截至 T−1 的20个交易日平均成交金额，至少10日有效历史；停牌日按零成交计算，IPO历史不足时保留空值。按当日统计池中历史成交金额排名分成三组，平值同组。
- 市场日序列按完整交易日历排列，只向后滚动，不跨股票滚动、不反向填充。
- 全市场共同环境特征不能用单因子日横截面RankIC筛选，其价值通过模型消融验证。
- T日行情入库和盘后成交时点限制沿用原插件说明；此回测是原有历史研究口径，不能直接解释为实盘可成交收益。

## 候选特征

1. `market`：市场收益均值/中位数、上涨比例、收益四分位差、涨跌停比例、5/20日市场趋势、标准化市场冲击、全市场放量、前10%成交金额集中度。
2. `liquidity`：历史成交金额排名、个股当日放量、高/低成交金额组当日收益、组间收益差及5日均值。
3. `relative`：个股减市场和所属成交金额组收益、当日收益排名、相对市场5/20日趋势。
4. `interaction`：市场冲击×个股相对收益、下跌环境×相对收益、组间轮动×历史成交金额排名、市场放量×个股放量。

输出特征分组、计算口径、覆盖率与每日市场诊断产物。训练参数可选择特征组；同一增强ETL用于全部消融，避免重复计算158个特征。

## 实验协议（结果查看前固定）

- 训练区间 `[2015-01-01, 2023-01-01)`，沿用时间顺序内部验证和标签边界隔离；模型早停沿用L2。
- 外部筛选区间 `2023-01-01至2024-12-31`，只在此区间比较候选组合。原有2023至2026基线不直接用于特征挑选。
- 最终确认区间 `2025-01-01至数据末日`，只比较筛选阶段选定的一个增强方案与基线，不根据最终结果继续调参。
- 首轮固定4个方案：原始158；158+market；158+market+liquidity+relative；158+全部4组。其余模型参数、随机种子42、训练样本和交易费用一致。
- 主指标：日均RankIC、扣费后Top10/Top20年化收益、Sharpe和最大回撤。辅助报告全部已有TopN、分年与市场涨跌环境表现、日配对指标差异。
- 筛选规则固定为RankIC、扣费后Top10年化收益、Top20年化收益三者均超过基线；合格方案中选RankIC最高者。若没有合格方案，只确认RankIC最高的增强方案并明确报告权衡，不称为全面提升，不再根据最终确认结果调参。不用单日或Top1的偶然高收益代替稳定性证据。
- 原始训练任务已成功且训练配置符合本协议，可复用其模型；另检查增强ETL的原始字段与基线一致。独立增强ETL增加26个候选特征，共184个特征。
- 保留所有任务ID/Run ID、完整配置、特征列表、模型重要性、回测产物和失败结果。提交成功不等于运行成功；上游仅在 `succeeded` 后用于下游。

## 实施与验证

1. 完成目录复制与注册隔离，开发纯Polars横截面计算和ETL输出契约。
2. 增加训练特征组选择，确保预测使用训练metadata中的特征顺序。
3. 本地验证因果性：改写未来数据不改变历史特征；当天金额跳升不改变历史分组；停牌、复权、平值和历史不足处理；市场池不依赖标签/可买性。
4. 构建并安装远程插件，检查注册、资源、数据覆盖后提交增强ETL。

6. 将执行记录和结果写到本目录，区分已实现、已提交、已成功及实测结论。
